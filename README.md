# Лабораторная работа №4: Параллельное перемножение матриц с использованием CUDA

## 1 Цель работы

Исследование эффективности параллельного перемножения квадратных матриц на графическом процессоре (GPU) с использованием технологии NVIDIA CUDA. Сравнительный анализ производительности с классической CPU-версией при различных конфигурациях расчетной сетки (блоков).

## 4 Алгоритм работы CUDA-программы
1. CPU генерирует случайные матрицы A и B в RAM
2. Данные копируются из RAM в видеопамять GPU
3. Запускается CUDA-ядро — все потоки параллельно вычисляют элементы C
4. GPU синхронизируется (ожидание завершения всех потоков)
5. Результат копируется обратно из видеопамяти в RAM
6. Программа выводит время выполнения

## 7. Анализ результатов

### 7.1 Влияние размера блока
Размер блока (thread block) является критическим параметром для производительности CUDA-программ, так как он определяет, сколько потоков будет выполняться одновременно внутри одного мультипроцессора (SM) GPU.


- Для малых матриц (N=200-400): Размер блока оказывает незначительное влияние. Блок 8×8 показывает даже немного лучшее время (0.000276 с против 0.000355 с для 32×32). Это связано с тем, что матрица целиком помещается в небольшое количество блоков, и оверхед на создание потоков доминирует над вычислительной нагрузкой.

- Для средних матриц (N=800-1200): Начинает проявляться преимущество блока 16×16 и 32×32. Блок 32×32 на N=800 работает на 44% быстрее блока 8×8 (0.00637 с против 0.00920 с).

- Для больших матриц (N=1600-2000): Размер блока 32×32 демонстрирует наилучшую производительность. На N=2000 блок 32×32 быстрее блока 8×8 на 47% (0.0967 с против 0.1424 с).

### 7.2 Зависимость от размера матрицы
Вычислительная сложность алгоритма умножения матриц составляет O(N³). По мере роста N, количество операций увеличивается кубически, что должно приводить к соответствующему росту времени выполнения.


- Для малых N (200-400): Время растет медленно (от 0.00028 с до 0.00123 с для блока 8×8)

- Для средних N (400-1200): Наблюдается квадратично-кубический рост. Переход от 400 к 1200 (увеличение N в 3 раза) увеличивает время примерно в 25 раз (для блока 32×32: 0.00097 → 0.02127 с ≈ 22×), что близко к теоретическому O(N³).

- Для больших N (1200-2000): Рост становится более предсказуемым и следует кубической зависимости. Увеличение N с 1200 до 2000 (в 1.67 раза) увеличивает время в ≈4.5 раза (0.02127 → 0.09670 с ≈ 4.54×), а 1.67³ = 4.66× - это практически O(N³).

## 9. Выводы
В ходе выполнения лабораторной работы было проведено исследование эффективности параллельного перемножения матриц на GPU с использованием технологии CUDA. Эксперименты выполнялись на ускорителе NVIDIA Tesla T4 в среде Google Colab для матриц размером от 200×200 до 2000×2000 с тремя конфигурациями блоков: 8×8, 16×16 и 32×32.

Основные результаты:

- Значительное ускорение относительно CPU. Максимальное ускорение составило 503× для матрицы 1600×1600. Даже для матрицы 2000×2000 ускорение остаётся высоким — 487×, что подтверждает эффективность использования GPU для задач умножения матриц.

- Оптимальный размер блока — 32×32. Для матриц размером 800×800 и более эта конфигурация показывает наилучшую производительность. На матрице 2000×2000 блок 32×32 быстрее блока 8×8 на 47%

- Подтверждение теоретической сложности O(N³). Экспериментальные данные хорошо согласуются с теорией: при увеличении N с 1200 до 2000 (в 1.67 раза) время выполнения выросло в 4.54 раза, что близко к теоретическим 1.67³ = 4.66×.

- Малые матрицы — исключение из правил. Для матриц размером 200×200 блок 8×8 оказался быстрее блока 32×32 (0.000276 с против 0.000355 с). Это связано с тем, что на малых размерах накладные расходы на создание большого количества потоков превышают выигрыш от параллелизации.
